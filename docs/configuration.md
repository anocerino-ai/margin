# Configuration reference

All environment variables use the `MARGIN_` prefix. Server environment variables override `.env`; saved provider overrides subsequently replace their corresponding connection values. Do not put secrets into frontend build variables.

## Authentication and storage

| Variable | Default / purpose |
| --- | --- |
| `MARGIN_ADMIN_EMAIL` | Empty; sole administrator email |
| `MARGIN_ADMIN_PASSWORD_HASH` | Empty; generated by `scripts/admin.py` |
| `MARGIN_COOKIE_SECURE` | `false` locally; set `true` behind HTTPS |
| `MARGIN_ENV` | `development`, `test`, or `production` |
| `MARGIN_API_TOKEN` | Legacy/test bearer setting; production validation currently still requires at least 32 characters, even with admin login. It does not bypass admin sessions when an admin is configured. |
| `MARGIN_STORAGE` | `sqlite`; alternatives `d1_worker` and direct `d1` |
| `MARGIN_SQLITE_PATH` | Project `margin.db`; Compose pins `/app/data/margin.db` |
| `MARGIN_CREDENTIALS_PATH` | `data/providers.json`; Compose pins `/app/data/providers.json` |

Do not set `MARGIN_ENV=production` without satisfying the current token guard. Remote hosting also requires HTTPS, secure cookies and a single API process. The token guard is separate from user login.

## Provider settings

| Variable | Purpose |
| --- | --- |
| `MARGIN_OPENROUTER_API_KEY` | Classification and generation |
| `MARGIN_FIRECRAWL_API_KEY` | Source extraction for generation |
| `MARGIN_RESEND_API_KEY` | Digest sending |
| `MARGIN_EMAIL_FROM` | Sender name/address |
| `MARGIN_EMAIL_RECIPIENT` | Digest recipient |
| `MARGIN_OPENROUTER_MODELS` | Comma-separated model IDs, used to seed an empty model catalog |

Use Settings for individual connection updates. Model rows are persisted in SQL: changing the model seed variable does not overwrite an existing catalog.

## Workload limits

| Variable | Default | Meaning |
| --- | --- | --- |
| `MARGIN_MAX_ARTICLES_PER_FEED` | 20 | Maximum entries read per feed |
| `MARGIN_MAX_NEW_ARTICLES_PER_RUN` | 20 | Bound on new articles processed per discovery |
| `MARGIN_CONTEXT_CHAR_BUDGET` | 48000 | Character budget for generation context, not an exact tokenizer count |
| `MARGIN_LLM_MAX_OUTPUT_TOKENS` | 5000 | Generation output bound; classification uses a smaller cap |

## Remote persistence

`MARGIN_D1_WORKER_URL` and `MARGIN_D1_WORKER_TOKEN` configure the recommended candidate bridge. The separate direct REST adapter uses `MARGIN_D1_ACCOUNT_ID`, `MARGIN_D1_DATABASE_ID` and `MARGIN_D1_API_TOKEN`. Multi-statement operations in that direct adapter are gated; it is not a substitute for validated bridge transactions.

## Runtime settings in SQL

The UI persists discovery enablement/frequency/day/hour/minute/timezone, classification confidence threshold, crawl cache duration and digest enablement. Sources, topics and model order are separate SQL catalogs. Save these settings before running a job.

Docker Compose explicitly pins SQLite. Editing only `.env` does not override an `environment` value in Compose; see the [D1 guide](cloudflare.md) before changing deployment storage.
